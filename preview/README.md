# Game jam preview

A single generated page that showcases the game jam. `index.html` is built by `generate.py` from the numbered game folders; nothing on the page is hand-edited.

## The page

- Header and footer are the real warpedvisions.org header/footer, vendored from the site's Hugo theme (see [Theme fidelity](#theme-fidelity)) so the page reads as part of the same site.
- The main view is a single 3D "console" carousel. No hero/intro text between the header and the console; header goes straight into it.
- Only game folders appear. `lib/` and `tools/` are not shown on this page.

## The console

The console has two parts: a **static frame** (always visible, full-width/height labelled buttons — the TV's physical control chrome) wrapped around an **inner cube** that does the actual 3D rotation. A literal 90°-rotated cube face is edge-on to the camera at rest — invisible and unclickable — so the buttons themselves can't be rotating faces; they stay fixed on the frame while the screen content spins inside its window.

- **Left / right** (frame buttons, `rotateY` on the inner cube) page between games, one at a time. This is how you browse the jam.
- **Up / down** (frame buttons, labelled with the name of the face you'll land on, `rotateX` on the inner cube) page through the current game's faces, Rolodex-style, wrapping:

  1. **Play** — the live cart embed, or `(GAME NOT READY)` if the cart isn't built yet or has no captured label. Looks like a live screen.
  2. **Download** — the `.p8` download link and the local run command.
  3. **About** — README, then DESIGN.md, then PLAN.md, then CLAUDE.md guidance in sequence, whichever exist for that game, in one combined face.

  Down from Play goes to Download; down again reaches About; down again wraps back to Play. Up reverses. A game that has no live embed opens on About by default rather than an empty Play screen.

Play looks like a live screen. Both back faces (Download and About) share a dark-background, terminal-green, monospace "mock monitor" look, distinct from Play.

Rotation is pure CSS: `perspective` + `rotateX`/`rotateY` on the inner cube (`transform-style: preserve-3d`), animated by CSS transitions. JS only toggles the cube's transform and swaps its front face's content between the exit and re-entry halves of the animation; there's no animation loop or drag physics. Behaviour doesn't change at narrow viewports, the whole frame scales down instead.

The cube pivots from the edge it's heading toward (`transform-origin: right/left/top/bottom`), not its own center — a shallow box rotating around its center shrinks symmetrically toward the middle and reads as a fade, not a turn. Hinging on an edge instead gives an asymmetric swing (one edge anchored, the other sweeping open like a door or a page turning), which reads unambiguously as rotation.

Below the console, a nameplate panel (matching the frame's background, so it reads as attached rather than floating) shows just the game's title (its README's `# ` heading, verbatim — some games don't have a real name yet and will show something like "1 README" until their README is updated) and its tagline. No game-number or position counter; the frame buttons and the console itself are navigation enough.

The About face's text is scrollable (it's often the longest content on the page: README, DESIGN.md, PLAN.md, and CLAUDE.md guidance concatenated) with a visible thin scrollbar so that's obvious. On touch devices, a vertical drag that starts on the screen content scrolls it instead of flipping to the next face; only drags starting on the frame trigger face navigation, since both gestures are vertical and would otherwise conflict.

## Theme fidelity

The real warpedvisions.org theme (Hugo, source at `~/projects/sites/w42/themes/w42` on this machine) is vendored into [`theme/`](theme/): `theme-vars.css`, `header.css`, `warped.css`, and `warped.js`. `generate.py` links these directly rather than re-approximating the site's styles inline, so the page stays pixel-faithful to the real site (including the coloured top/bottom "flourish" bars, which `warped.js` injects) and doesn't drift out of sync.

This also means the page uses the theme's own `.dark` body-class convention for its theme toggle (matching the vendored CSS), and the page width follows the theme's real `--main-width: 640px` rather than a custom wider layout; the console and its bezel are sized to fit that column.

The footer text is kept verbatim from the real theme, including "Powered by Hugo," even though this page is generated by `generate.py`, not Hugo. Fidelity to the source wins over local accuracy here.

## Building

`index.html` is generated, not hand-edited. Regenerate it after adding a game, changing a spec, or capturing a cart's Pico-8 label:

```sh
python3 generate.py
```

This scans the numbered game folders, embeds their docs, copies each existing cart into `downloads/` and, for any cart with a captured label, exports a playable build into `exports/<n>/`. Both `downloads/` and `exports/` are generated output (gitignored); the page reads them at runtime via relative paths, so the whole `preview/` folder (including the committed `theme/` assets) is self-contained and can be deployed on its own.

A cart without a captured label (Esc menu in Pico-8, or the `label` console command) shows a placeholder instead of a live embed — Pico-8 refuses to export until one exists. Capture it once in the editor and rerun the generator.

## Viewing

Pico-8's web export needs to be served over HTTP; opening `index.html` directly (`file://`) will fail to load the embed due to browser fetch restrictions. Serve it locally instead:

```sh
python3 -m http.server 8000
```

Then open `http://localhost:8000/`. For a real deploy, rsync the `preview/` folder (including its generated `downloads/` and `exports/` subfolders) to a folder on a live webserver; no server-side logic is required, it's static files.
